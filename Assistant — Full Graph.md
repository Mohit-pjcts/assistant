**Reading this diagram**

- The top row (`compact_history → recall_memory → supervisor → extract_memory`) is the only part that is a real `StateGraph` — this is exactly what Studio shows you today.
- `supervisor` itself is also a `create_agent` ReAct loop (model ⇄ tools), same shape as every specialist below it — not drawn expanded here since its own tool list is just the 5 specialist-delegate wrappers + `render_ui` + the confirmation tool.
- Every dashed arrow out of `supervisor` is **not a graph edge** — it's a Python function call (`_invoke_agent_graph`) that runs a specialist's compiled graph to completion in isolation, then returns its final message back into the supervisor's own tool-result. Recursion, streaming, and interrupts all still work across this boundary (proven live, see CLAUDE.md Phase 16/18 notes) — it just isn't graph structure Studio can see.
- `life_admin_agent`'s tool list above was generated with `mcp_tools=[]` (no local Gmail/Calendar MCP server running in this environment) — in the real running app it also carries the write_tools.py gated send_email/calendar/filter wrappers once the MCP server loads.
